# 0019. 標準ライブラリで無理なく書ける依存は持たない (cobra と x/time を外す)

- 日付: 2026-10-21
- 状態: 採用

## 背景

ADR 0017 で依存の取り込み方 (7 日待機・SHA 固定・govulncheck) は固めたが、依存そのものが少ないほど攻撃面は小さい。
直接依存のうち `github.com/spf13/cobra` (と間接の `spf13/pflag`・`inconshreveable/mousetrap`) と `golang.org/x/time` は、
使っている機能が小さく標準ライブラリで置き換えられる。

- cobra: サブコマンド、`--x` / `-x` の短縮形、ヘルプ表示、引数の数の検査、`--version` だけを使っていた
- x/time/rate: LookupEvents の「毎秒 2 回・バースト 1」の `Wait` だけを使っていた

## 決定

- **CLI は標準の `flag` の上に書いた小さなコマンド層** (`cmd/arata/cli.go`) にする。ヘルプの書式とエラーの文言は cobra / pflag と同じにし、
  ルートのヘルプのゴールデンとコマンドレベルの e2e で挙動を固定する。フラグと位置引数が混ざってよい (`approve <id> --note x`)
- **LookupEvents のレート制限は自前の `IntervalLimiter`** (`internal/collect/cloudtrail/ratelimit.go`)。前回の枠から `1s/n` 空けるだけの
  トークンバケット (バースト 1) と同じ挙動で、時刻と待ちは差し替えてテストする。スロットル時の指数バックオフ (適応リトライ) は従来どおり
- **SQLite (`modernc.org/sqlite`) は残す**。索引・トランザクション・集計クエリを自前で持つ実装量と不具合の危険が、依存を減らす利点を上回る
- 新しい依存を足すときは「標準ライブラリで無理なく書けるか」を先に確かめ、書けるなら書く

## 検討した選択肢

- **cobra を残す**: 機能は十分だが、使わない機能 (シェル補完の生成、Windows 向けの mousetrap など) ごと取り込むことになる。却下
- **別の小さな CLI ライブラリ**: 依存の種類が変わるだけで攻撃面は減らない。却下
- **x/time を残す**: `golang.org/x` は Go チームの管理で信頼度は高いが、使う機能が十数行で済む。却下

## 結果

- go.mod の require が 4 つ減る (直接 2: cobra・x/time、間接 2: pflag・mousetrap)
- 引き受けるコスト: cobra が自動で足していた `completion` コマンド (シェル補完スクリプトの生成) は無くなる
- 引き受けるコスト: コマンド層の不具合は自分で直す。ヘルプ書式とエラー文言は `cmd/arata/cli_test.go` で固定する
- サブコマンドを束ねるだけのコマンドに未知のサブコマンドを渡すと (`arata config bogus`)、ヘルプを出して終了コード 0 ではなく、
  未知のコマンドとして終了コード 2 にした (定期実行の打ち間違いを成功扱いにしないため)
