# 0053. 読み取り専用ロールに、読ませないロググループの名前を受けるパラメータを足し、中身を読む操作を明示の Deny で止める

- 日付: 2026-11-14
- 状態: 採用

## 背景

配布用の読み取り専用ロール (`deploy/iam/readonly-role.yaml`) は、Logs Insights の action (`logs:StartQuery` など) を `Resource: '*'` で許している。
arata がどのロググループを読むかは利用者の設定 (`sources`) で決まるので、ロールの側では絞っていなかった。

利用者によっては、個人情報だけを書くロググループ (メールの送信ログなど) があり、監査のロールにも読ませたくない。
`sources` に書かなければ arata は読まないが、それは arata の設定の話で、ロールを引き受けられる主体が読めることは変わらない。
ロールの側で「このロググループは読めない」と言える手段が無かった。

## 決定

**ロールのテンプレートにパラメータ `DeniedLogGroupNames` (ロググループの名前のカンマ区切り。既定は空) を足し、指定があれば、
そのロググループの中身を読む操作を明示の Deny で止める。**

- 空なら Deny の文を出さない (Condition)。今までのロールとポリシーは同じになる
- **明示の Deny** にする。Allow の `Resource` から外すだけにしない。後からほかのポリシー (管理ポリシーなど) がロールに付いても、Deny が優先される
- 止める action は、ログの行・項目の値を返す操作: `logs:StartQuery`・`GetQueryResults`・`GetLogRecord`・`GetLogEvents`・`FilterLogEvents`・
  `StartLiveTail`・`GetLogGroupFields`・`Unmask`。AWS の Service Authorization Reference で、ロググループかログストリームを対象に取る Read の操作から選んだ。
  arata が呼ぶのはこのうち `StartQuery` と `GetQueryResults` だけ
  - 一覧 (`DescribeLogGroups`) と `StopQuery` は中身を返さないので止めない。`arata doctor` の `log_group` (名前の一致) はそのまま使える
  - `logs:*` にはしない。対象を取らない action の当たり方を読み違えると、ほかのロググループの一覧まで止めるおそれがある
- ARN は名前ごとに 2 つ: `arn:*:logs:*:*:log-group:<名前>` (ロググループそのもの) と `arn:*:logs:*:*:log-group:<名前>:*`
  (その下のログストリーム。`GetLogEvents` の対象)
- **リージョンは `*`**。IAM のロールはリージョンを持たず、arata のソースはリージョンごとに書ける。スタックを置いたリージョンだけを止めると、
  別のリージョンの同じ名前のロググループが読めてしまう。止めすぎる側に倒す
- **アカウントとパーティションも `*`**。素の CloudFormation には並びの各要素に接頭辞を付ける関数が無く、`!Join` の区切りには関数
  (`AWS::AccountId` など) を書けない。ロールのポリシーが効くのは、このロールが触れるロググループだけなので、`*` で困ることは無い
  (ほかのアカウントの同じ名前まで止めるのは、止めすぎる側)
- 名前は完全一致。パラメータの `AllowedPattern` で、ロググループの名前に使える文字 (英数字と `_ - / . #`) のカンマ区切りだけを通す。
  ワイルドカード (`*` `?`)・空白・コロン・ARN・空の要素は、スタックの作成・更新の時点で弾く
  (`*` 1 つで全部のロググループを止める、`a, b` の空白で 1 つも当たらない、を黙って通さない)
- arata の設定には何も足さない。**読ませないロググループは `sources` に書かない** (文書に書く)。
  書いた場合、run はそのソースだけを `ACCESS_DENIED` で失敗にして続ける (従来どおり)
- `arata doctor` は、クエリの検査で StartQuery が拒否されたら、`permission` の 1 行にまとめる。ロググループの名前と
  「ロールに action が無いか、読ませない設定 (DeniedLogGroupNames)。後者なら sources から外す」を出し、そのソースの残りの検査は行わない
  (これまでは、同じ拒否がクエリごとに `queries` の行として並んだ)。action が無いのか明示の Deny なのかは AWS のエラーの文言でしか
  分からないので、arata は判定しない

### 複数のロググループを 1 回で問い合わせる StartQuery

`StartQuery` は `logGroupNames` / `logGroupIdentifiers` で最大 50 のロググループを 1 回で問い合わせられる (API リファレンス)。
IAM は、明示の Deny が 1 つでも当たればリクエストを拒否するので、その中に Deny したロググループが 1 つでもあれば、問い合わせ全体が拒否される見込みである。
ただし、この場合の挙動をそのまま書いた AWS の文書は見つけられなかった (StartQuery の API リファレンス・CloudWatch Logs の権限リファレンス・
ID ベースのポリシーの例を確かめた)。実環境で確かめる項目として残す。

arata は 1 回の `StartQuery` に 1 つのロググループ (`logGroupName`) しか渡さないので、どちらであっても、ほかのソースの問い合わせには影響しない。
影響を受けるのは、このロールを人が使って複数のロググループをまとめて問い合わせる場合だけである。

## 検討した選択肢

- **Allow の `Resource` を、読ませるロググループの一覧にする (許可リスト)**: 最小権限としては素直だが、ソースを足すたびにロールの更新が要り、
  ほかのポリシーが付けば読めてしまう。「このロググループだけは読ませない」という要求には Deny が合う。採らなかった
- **ARN をそのまま受ける (`DeniedLogGroupArns`)**: アカウントとリージョンを利用者が書けるが、`:*` の付け忘れ・付けすぎで当たらない Deny を作りやすく、
  当たっていないことに気付けない。名前だけを受けて、テンプレートが 2 つの形を組み立てるほうが間違えにくい。採らなかった
- **`arn:${AWS::Partition}:logs:${AWS::Region}:${AWS::AccountId}:log-group:<名前>` の形にする**: 素の CloudFormation では、
  名前の数を固定の上限 (`!Select` を並べる) にしないと書けない。上限を超えた名前が黙って無視される形になるので、採らなかった。
  `AWS::LanguageExtensions` の `Fn::ForEach` なら書けるが、Transform が要り (`CAPABILITY_AUTO_EXPAND`)、sandbox の CfnInclude での取り込みも変わる。採らなかった
- **リージョンをスタックのリージョン (`AWS::Region`) にする**: 上の理由で書けないうえ、別のリージョンの同じ名前を読めるままにする。採らなかった
- **タグで止める (`aws:ResourceTag/...` の条件で Deny)**: ロールの更新が要らず、ロググループの側で宣言できる。しかしタグを外せば読めるようになり、
  タグを付けられる主体が Deny を動かせる。どの action がタグの条件を評価するかも action ごとに確かめる必要がある。まずは名前で止める。採らなかった
- **arata の設定に「読まないロググループ」を足す**: arata は `sources` に書いたものしか読まないので、設定の側には既に手段がある。足りないのはロールの側。採らなかった
- **ログを外へ出す操作 (`logs:CreateExportTask`・`PutSubscriptionFilter` など) も Deny に入れる**: 中身を外へ出せる操作だが書き込み系で、このロールには無い。
  一覧にきりが無く、この Deny の役割 (読み取りのロールに読ませない) から外れる。入れなかった

## 結果 (良い点・引き受けるコスト)

- 利用者は、スタックの更新 1 回で、監査のロールに読ませないロググループを宣言できる。ほかのポリシーが付いても効く
- 既定は空なので、指定しない利用者のロールは変わらない
- arata の読み取り専用の性質・必要な action の一覧は変わらない (Deny は権限を足さない)
- 名前の変更・新しいロググループには追従しない。個人情報を書くロググループを足したら、利用者がパラメータにも足す
- 同じ名前のロググループは、どのリージョン・アカウントのものも読めなくなる (止めすぎる側。必要になったら ARN を受ける形を新しい ADR で検討する)
- ロールのインラインポリシーには大きさの上限がある。名前 1 つにつき、名前の長さの 2 倍 + 60 文字ほどを使う
- この Deny は、このロールにだけ効く。ロググループを読めるほかの主体 (管理者など) や、ログを外へ出す書き込み系の操作は止めない
- `arn:*:…` (パーティションのワイルドカード) を IAM が受け付けること、複数ロググループの StartQuery の挙動は、テストでは確かめられない
  (実 AWS に接続しない)。実環境で 1 度確かめる
