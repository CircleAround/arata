# 0018. LLM 要約と通知は aratam が担い、arata とは出力リソースだけで連携する

- 日付: 2026-10-21
- 状態: 採用

## 背景

ADR 0001 で、arata は収集・保存・差分判定・レポート生成までを担い、LLM 要約と通知は組み込み側に任せた。
しかし組み込み側 (要約の手順、重大度の下限、LLM 失敗時のフォールバック、二重送信の防止) は監査対象ごとに毎回作ることになり、
9-1 章で「規則で固定する」とした部分が実装ごとに抜け落ちる恐れがある。

## 決定

組み込み側の標準品として、同じリポジトリに別コマンド `aratam` を置く。

- aratam は arata が `--out` に書いた `report.json` / `report.md` だけを入力にする。arata を呼ばず、arata のパス・AWS の監査ロール・ストアを知らない。
  組み合わせは cron / シェル側で行う (`arata run --out X` → `aratam notify --in X`)。
- arata 自体は変えない。ADR 0001 の「エンジン内で LLM を使わない」は維持する。
- 重大度の下限による送り先の振り分け、finding の欠落の補完、LLM 失敗時の report.md 送信、入力が無い・古いときの通知は、aratam の規則として固定する。LLM には要約と分類だけをさせる。
- LLM は Bedrock と `claude -p` に対応し、将来 OpenAI を足す。通知は Slack Incoming Webhook から始める。
- ネットワーク呼び出しは標準の `net/http` で書く。Bedrock だけは AWS SDK を使ってよい。

## 検討した選択肢

- aratam が arata のパッケージを import し、1 つのバイナリで収集から通知まで行う: AWS の監査ロールと LLM・通知の鍵を同じプロセスが持つことになり、監査の土台に LLM の依存が混ざる。却下
- aratam が arata をサブプロセスで呼ぶ: arata のパス解決と版の不一致に気を配る必要があり、AWS の認証情報が aratam のプロセス環境を通る。却下
- 組み込み側を利用者に任せたままにする (現状): 規則として固定したい部分が実装ごとに抜け落ちる。却下

## 結果

- 権限を分けられる (arata は AWS 読み取りだけ、aratam は LLM と Webhook だけ)。別の OS ユーザーで動かすこともできる
- aratam のテストは report.json のゴールデンと LLM 応答の固定値だけで書け、AWS のモックが要らない
- arata だけを使う最小構成 (レポートを人が読む) もそのまま残る
- report.json の形が arata と aratam の契約になる。同じリポジトリに置き、`internal/report` の型を共有してずれをコンパイル時に検出する
- aratam を使う場合は、cron 側で 2 つのコマンドをつなぐ設定が要る
