# 0014. 既定のプロファイルを実行時に暗黙で効かせず、推奨設定を雛形として書き出す

- 日付: 2026-10-21
- 状態: 採用

## 背景

Step 3 で週次チェックなどが増える。これまでの設定は `profiles` に `default-daily` のような省略記法を書け、版が上がって daily のチェックが増えると、
設定を変えなくても新しいチェックが黙って走り始める。逆に、省略記法を使わず名前を並べた設定では、増えたチェックに誰も気づかない。
どちらの場合も「今この顧客で何が走っているか」が設定ファイルを読んでも分からない。監査エンジンとして、
「静かだったのは平和だからか、見ていなかったからか」(coverage) と同じ問いが設定の側にもある。

## 決定

- エンジンは実行時に暗黙の既定のプロファイルを持たない (`profiles` 必須は現状どおり)。**実行されるのは設定ファイルに書いたチェックだけ**
- 推奨の設定は `arata config init` が **全プロファイル・全チェック・各チェックの既定パラメータを明示したコメント付き YAML** として書き出す。
  雛形は `default-*` を使わない。チェック一覧・既定値は Registry と `config.DefaultChecks()` から生成し、ゴールデンと「Load が通る」「既定値と一致する」テストで固定する
- 版を上げたときの追従は `arata config init --diff -c config.yaml` で行う (入っていないチェック、既定値と違うパラメータ、未知のキー)。
  人が差分を見て設定に取り込む。実行時の判断材料として、どのプロファイルにも入っていないチェックがあれば run / evaluate / doctor が `CHECK_UNUSED` を警告する
- 実際に効いている中身は `arata profiles` で見る (省略記法を展開し、パラメータの由来を overrides / checks: / 既定値で示す)
- `default-<cadence>` は手書きの設定と既存の設定のために残す (後方互換)。位置づけは「増えたチェックも自動で入ってよい」と人が判断した場合の書き方で、推奨ではない
- プロファイルごとの上書き (`profiles.<name>.overrides.<check>`) は判定のパラメータだけを許す。集計条件 (paths / methods / failure_statuses / statuses / exclude_paths) は
  Logs Insights の集計クエリに使われ、metrics は全プロファイルで共有・置き換え保存 (ADR 0009) なので、プロファイルごとに変えると平常帯が壊れる。書いたら CONFIG_INVALID

チェックのパラメータ (`checks:`) の既定値は、従来どおり書かなければ実行時にその版の既定値が効く (閾値の改善は版に追従させたい。`--diff` は書いた値が既定値と違うものだけを出す)。
「暗黙にしない」のは **どのチェックを走らせるか** であって、閾値の既定値ではない。

## 検討した選択肢

- **profiles を省略可能にし、組み込みの既定のプロファイルを実行時に効かせる**: 設定が短くなるが、版が上がると走るチェックが黙って変わる。設定から何が走るか読めない。却下
- **`default-*` を廃止する**: 既存の設定 (examples/config.yaml、試用中の顧客) が読めなくなる。雛形で使わず、CHECK_UNUSED と `--diff` で入れ忘れに気づける形にとどめた
- **雛形を手書きの YAML ファイルとして embed する**: コメントは自由に書けるが、チェックや既定値を足したときに直し忘れる。生成にし、説明文 (Descriptions) の書き漏れはテストで弾く
- **overrides で集計条件も変えられるようにし、metrics をプロファイル別に持つ**: ストアのキーとクエリ回数がプロファイル数倍になる。必要になってから考える

## 結果

- 導入手順は `config init → doctor → init → run` になる (ルートのヘルプ、README、`arata help ai`)
- 版を上げた後に人が `--diff` を見て設定を更新する手間が残る。忘れても CHECK_UNUSED が毎回警告する
- 雛形のゴールデン (internal/scaffold/testdata/config.yaml) はチェックや既定値を変えるたびに更新が要る
