# 0003. JSONL 原本 + SQLite 派生の二層ストア

- 日付: 2026-10-21
- 状態: 採用

## 背景

「平常状態」と「今日のログ」を比べるには過去の観測を手元に持つ必要がある。
毎回 AWS へログを取りに行くのは不経済で、Logs Insights はスキャン量課金でもある。
一方でストアが壊れたり形式を変えたくなった時に、原本から作り直せる必要もある。

## 決定

- `raw/<source>/<YYYY-MM-DD>.jsonl`: collect が取得した正規化レコードの原本。追記のみ。人が読め、S3 へそのまま退避できる
- `audit.sqlite`: raw から再構築できる派生物。差分判定と期間集計のためのインデックス (`arata rebuild` で作り直す)
- `allowlist.yaml`: 人が承認した既知リスト。git 管理 (ADR 0004)
- バックエンドはローカルディレクトリと S3 プレフィクスの 2 実装。S3 は実行開始時に取得し終了時に書き戻す
- 保持期間は設定で指定し、`run` の最後に自動削除する。メトリクスは前年同月比較のため 13 か月を既定にする

## 検討した選択肢

- テキストログのみ: 差分判定のたびに全件を読み直すことになる
- SQLite のみ: 原本の可搬性と監査性が落ち、スキーマ変更時に戻れない
- DynamoDB / RDS: 運用対象が増える。オンプレ実行と相性が悪い

## 結果

- AWS への問い合わせは「直近ウィンドウの集計」だけになり、費用が読める
- 集計のみ保存するので SQLite は数十 MB 程度に収まる見込み
- ストアの排他 (同一顧客の同時実行) をエンジン側で扱う必要がある (`STORE_LOCKED`)
