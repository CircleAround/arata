# 0030. 画面への分散した集中と「A のあと B」の連鎖 (`endpoint_abuse`) を、画面ごとの時間幅の集計とふだんの p99 で判定する

- 日付: 2026-11-03
- 状態: 採用

## 背景

使い捨てのメールアドレスでの会員登録の連続や、登録の直後にスパム・フィッシングのメッセージを送る流れは、1 IP あたり 1〜数件に分散して来ることがある
(同じ User-Agent、CAPTCHA も通過)。IP ごとの連打を見る login_bruteforce や WAF のレートベースのルールでは拾えない。
多数の IP から短い時間に同じ画面へ集中する形と、「ある画面に来た IP がすぐ別の画面に来る」連鎖を、ふだんと比べる必要がある。

利用者の運用では、登録を拒否せず保留して運営が確認することがある。誤って正規の利用者を止める提案は害が大きい。

## 決定

- 新しい daily・event 型のチェック `endpoint_abuse`。画面 (`checks.endpoint_abuse.endpoints`: 名前・パスの glob・メソッド・ステータス・数えるソース) は利用者が設定で増やす。
  既定は空 = 何もしない (Insights のクエリも流さない。ADR 0014)
- 集計: http_access のソースが画面ごとに 1 本、`(時間幅 (既定 10 分), IP, UA)` ごとの件数と最初・最後の時刻を Insights で返させ、件数・異なり IP・同じ UA の広がり・連鎖を Go で数える。
  日次集計として `endpoint_abuse_count` / `_ips` / `_ua_ips` / `_follow` (key は `<画面>|<HH:MM>`) を保存する。IP と UA の原文は保存しない (UA は sha256 の先頭 8 文字)
- 判定: 時間幅ごとの異なり IP 数が `min_distinct_ips` 以上かつふだん × factor を超えたら medium、件数が `min_count` 以上かつふだん × factor を超えたら low。
  同じ UA の広がりは根拠に添えるだけ。連鎖 (`follow_ups`: from の画面に来た IP のうち within 以内に to の画面に来た IP の数) は medium。重大度は medium まで
- ふだん = 過去 `baseline_days` 日のうちログを収集した日 (`lines_total` のある日) の全部の時間幅 (無い幅は 0) の p99。収集した日が `min_baseline_days` 未満の間は絶対の閾値だけ
- 結果は事実 (件数・異なり IP・ふだんの上限・同じ UA の IP 数) として伝え、遮断の提案にしない。playbook も「確認・保留の運用へつなぐ」
- 今回は http_access のソースだけ。wafv2 (ステータスが無く UA はヘッダーの配列の中) と、アプリのログからの追加フィールド (メールのドメインなど) は次の段階

## 検討した選択肢

- **Insights で件数・count_distinct・UA の上位・連鎖をそれぞれ集計する**: 指標ごとにクエリを分けるので画面 × 3 回スキャンし、count_distinct は概数。
  1 本の `(時間幅, IP, UA)` の集計から Go で数える形にした。代わりに行数の上限 (10000) を引き受け、1 日ずつ流して、当たれば時間で半分に分けて引き直す
- **IP ごとの件数の平常帯 (login_bruteforce の方式) を画面に広げる**: 1 IP あたり 1 件の分散した登録は拾えない。却下
- **ふだんを日次の中央値にする**: 時間幅の集中は日の合計に埋もれる。時間幅ごとの値の p99 にした。まれにしか使われない画面は p99 が 0 になり、絶対の閾値で判定する
- **ふだんの日数を「画面の集計のある日」で数える**: 来訪の少ない画面ほどいつまでも判定しない (ADR 0027 と同じ問題)。ロググループ全体の行数 (`lines_total`) のある日で数える。
  run の stats に印を足す案 (ADR 0027 の `trail_collected`) は、Web のログに行の無い日がほぼ無いので見送った
- **WAF のログも今回から数える**: ステータスと UA の扱いが違い、チェックの Needs を設定から決める必要がある。次の段階にした
- **結果に遮断 (IP の拒否・登録の停止) の提案を付ける**: 正規の利用者を止め得て、利用者の方針 (保留して確認) にも合わない。事実だけにした

## 結果

- 良い点: 1 IP 1 件に分散した登録・送信の集中と、登録の直後の送信の連鎖を、ふだんと比べて報告できる。IP・UA の原文・リクエストの内容を保存しない
- 引き受けるコスト: 画面ごとに 1 回、既存の集計と同じ範囲をスキャンする (画面 2 つで http_access のソースのスキャンは約 1.5 倍)。`max_scan_gb` で上限を掛ける。
  時間幅の行がまとまっているため連鎖の時刻は近似。複数のソースが同じ画面を数えると件数が重なる (`sources` で選ぶ)
