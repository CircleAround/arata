# lucr-3-2023-09: ID プロバイダの乗っ取りから AWS に入り、秘匿値を集め、IAM に居座り、検知を止める (LUCR-3 / Scattered Spider)

## 概要

- 公開日: 2023-09-20
- 人の認証情報 (買ったもの、SMS の詐欺、ヘルプデスクへのなりすまし) と MFA の回避で ID プロバイダに入り、そこから SaaS・CI・AWS へ進む攻撃者の手口。Permiso が複数の対応から報告した
- AWS では、マネジメントコンソールと CloudShell、S3 Browser を使う。自前のマルウェアではなく、正規の利用者と同じ道具で動く
- Secrets Manager の秘匿値を集め、IAM ユーザー・アクセスキー・ログインプロファイルを作って居座り、GuardDuty と CloudTrail を止める
- 目的は S3 やデータベース、SaaS のデータの持ち出し

## 出典

- Permiso "LUCR-3: Scattered Spider Getting SaaS-y in the Cloud" (2023-09-20): https://permiso.io/blog/lucr-3-scattered-spider-getting-saas-y-in-the-cloud

## arata では見えないもの

- **ID プロバイダと SaaS、ソースコードの置き場の中**: 侵入の入口と、MFA の登録、データの持ち出しの多くは AWS の外で起きる。arata は読まない
- **正規の人と同じ主体・同じ道具での操作**: フェデレーションのロールは既知なので `new_principal` は出ない。頼れるのは送信元の違い (`principal_new_source`) だけで、
  出典は、攻撃者が被害者に近い地域の送信元を選ぶと書く (arata は国を見ず、/24 の単位で新しいかだけを見る)
- **`iam_changes` の対象外の操作**: 既存のユーザーのパスワードの変更 (`UpdateLoginProfile`)、インスタンスのロールの付け替え
- **データの持ち出し**: S3 のオブジェクト、DynamoDB、RDS の中身の読み出しは、管理イベントに無い
- 検知を止めた後の操作 (CloudTrail が止まっていた間の記録は無い)
